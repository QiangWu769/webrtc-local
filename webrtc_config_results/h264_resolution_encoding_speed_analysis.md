
3. ✅ **编码器启动**: 分辨率切换时的初始化

## 🔍 深度分析

### 为何在360p停留这么久？

**可能原因**:

1. **带宽估计保守**
   - 初始降级后，BWE（带宽估计）给出了较低的估计值
   - 需要较长时间才能确认带宽充足

2. **Quality Scaler阈值设置**
   ```cpp
   当前阈值（推测）:
   low_threshold = 24   // 太高，恢复困难
   high_threshold = 37  // 降级过快
   ```

3. **网络波动**
   - 重传码率542 kbps（比上次13:28高55.7%）
   - 说明网络有丢包，系统保持低分辨率以保证稳定性

4. **恢复条件苛刻**
   - 需要连续稳定的高带宽才能恢复
   - 178帧（5.93秒）说明恢复条件不容易满足

### 逐步恢复的合理性

**恢复路径**: 360p → 540p → 720p → 1080p

**每级持续时间**:
- 360p → 540p: 178帧后（5.93秒）
- 540p → 720p: 120帧后（4.00秒）
- 720p → 1080p: 120帧后（4.00秒）

**观察**:
- ✅ 每级间隔约4秒是合理的
- ✅ 渐进式恢复避免反复波动
- ⚠️ 但初始在360p停留过久
